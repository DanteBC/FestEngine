
## Цель

Когда оператор что-то делает на сцене или правит строку, FestEngine отправляет
JSON-событие POST-запросом на URL из настроек феста. Получатель может быть
любым: приложение-компаньон, Telegram-бот через n8n, Home Assistant, оверлей
трансляции, лог таймингов.

Требования:

- **По умолчанию выключено.** Без URL FestEngine работает ровно как сейчас.
- **Не мешает шоу.** Сетевые вызовы не идут в UI-потоке, и никакой сбой хука не
  останавливает воспроизведение или проектор.
- **Без новых зависимостей.** Только стандартная библиотека Python.
- **Привычный формат.**
  - Тело, заголовки подписи и правила повторов — по
    [Standard Webhooks](https://github.com/standard-webhooks/standard-webhooks/blob/main/spec/standard-webhooks.md),
    так что получатели проверяют подпись готовыми библиотеками.
  - Свои заголовки нужны тем, кто проверяет статический ключ: n8n Header Auth,
    токены в стиле GitLab.

## A1. Что видит оператор

### Настройки

| Поле | Ключ конфига | Значение |
| --- | --- | --- |
| URL | `API Post URL` (уже в форке) | `""` = выключено. `debug` = писать события в лог вместо отправки (уже в форке). |
| Включено | `API Post Enabled` (уже в форке) | галочка **Send Webhooks** в меню |
| Секрет | `API Post Secret` (новое) | `whsec_<base64>`; `""` = без подписи |
| Свои заголовки | `API Post Headers` (новое) | объект `{"Имя": "значение"}`, редактируется построчно `Имя: значение` |

Есть две кнопки:

- **Generate** заполняет секрет: `whsec_` + base64 от 32 случайных байт.
- **Send test event** сразу отправляет `hook.test` и показывает код ответа.

**Секрет и заголовки независимы и оба необязательны.** Можно одно, оба или
ничего:

| Секрет | Заголовки | Типичный получатель |
| --- | --- | --- |
| есть | — | Всё, что проверяет подписи Standard Webhooks |
| — | `Authorization: Bearer …` / `X-Api-Key: …` | n8n Header Auth, простые API |
| есть | есть | Получатель за шлюзом, которому нужен ключ **и** подпись |
| — | — | URL со встроенным секретом (Home Assistant `webhook_id`) или получатель в локалке |

Окно настроек проверяет и предупреждает:

- **Имена заголовков** — валидные HTTP-токены. **В значениях** нельзя CR и LF.
- **Служебные заголовки переопределить нельзя:** `Content-Type`,
  `Content-Length`, `Host`, `User-Agent`, `webhook-id`, `webhook-timestamp`,
  `webhook-signature`. Регистр не важен.
- **URL не `https`, а секрет или заголовки заданы** — предупреждение («секрет
  уйдёт открытым текстом»), но сохранить можно.
- **Подпись под полями:** секрет и заголовки хранятся открытым текстом в
  `.fest` **и в его бэкапах `*.bkp.fest`**, которые `on_settings` пишет при
  каждом изменении конфига.

### Пропуски (собственное состояние FestEngine)

- **Как пометить:** строка считается пропущенной, если в заметке есть одно из
  слов **пропуск, пропущен, пропущена, skip, skipped**.
  - Ищется **целое слово**, без учёта регистра. `skipping intro` не считается.
  - Список хранится в `constants.py`.
- **Отображение:** пропущенная строка заметно выделяется в таблице.
- **Как вернуть:** убрать слово из заметки.
- **События:** только при **смене состояния** (см. A2).

### Меню, строка состояния, лог

- **Send Webhooks** — галочка в меню Fire. Неактивна, пока URL пустой.
  Выключена по умолчанию, чтобы репетиция никого не оповещала.
- **Строка состояния:** новое поле `Hook: off | 200 | retrying (3) | 410 —
  disabled | 422`.
- **Лог:** каждая отправка, повтор, отброс и ошибка пишутся с префиксом
  `[Webhook]`. **Никогда не пишутся:** секрет, подписи и значения своих
  заголовков.

## A2. Контракт

### Конверт (одинаковый для всех событий)

По рекомендованной форме Standard Webhooks:

```json
{
  "type": "row.move",
  "timestamp": "2026-10-27T15:20:47.641Z",
  "data": {
    "row": {
      "num": "116",
      "grid_num": "116",
      "row_type": "track",
      "fields": { "name": "Kaoru — Trinity Blood" },
      "notes": ">200 опоздали"
    },
    "after_num": "200",
    "dup_grid_num": "200a"
  }
}
```

**Поля верхнего уровня:**

| Поле | Смысл |
| --- | --- |
| `type` | Тип события, через точку, из таблиц ниже |
| `timestamp` | Когда оператор сделал действие, UTC ISO 8601 с миллисекундами. Не меняется при повторах. |
| `data.row` | Строка, о которой событие, или `null`, если строки нет |
| остальное в `data` | Поля, зависящие от типа события (таблицы ниже) |

**`data.row`:**

| Поле | Смысл |
| --- | --- |
| `num` | Идентичность номера: `get_num(row)`, у дублей — номер исходной строки (`"116"`). `null` у строк отсчёта. |
| `grid_num` | Ячейка № как есть (`"200a"` у дубля, `"brk"` у отсчёта). |
| `row_type` | `track`, `dup` или `countdown`. |
| `fields` | Все колонки, кроме №, files и notes: именованные группы regex (кроме начинающихся с `_`), у отсчёта — `name` (его текст). |
| `notes` | Заметка как сейчас. |

**Правила формата:**

- **Номера всегда строками** (`"007"`, `"183a"`, `"brk"`).
- **Никогда не отправляются:** локальные пути и колонка `files`.
- **Тело — UTF-8 JSON, сериализуется один раз.** Подписываются ровно те байты,
  которые уходят.
- **Совместимость:**
  - получатели игнорируют незнакомые типы и поля;
  - добавить тип или поле — не ломающее изменение;
  - переименовать или убрать — ломающее. Так не делаем, вводим новое имя.

### События

Событие шлётся там, где действие реально произошло. «ALREADY PLAYING!» в
`play_async` ничего не шлёт.

**Сценические команды** (живут 120 с, см. «Доставка»):

| `type` | Когда | Доп. поля в `data` |
| --- | --- | --- |
| `row.show` | **F1**: оператор показал задник строки. Авто-ZAD при F2 его не шлёт. | — |
| `row.play` | Запуск фонограммы/видео строки: F2, Enter, двойной клик или **F5** (продолжение остановленного трека) | `resumed`: `true` при F5 |
| `row.stop` | Shift+F2: трек уведён без конца выступления | — |
| `row.finished` | Трек/видео доиграл до конца (остановленный не считается) | — |
| `row.end` | Esc или F3 с End Show | — |
| `projector.clear` | Shift+F1 / Alt+F1 | `mode`: `"background"` или `"black"` |
| `system.emergency_stop` | Shift+Esc | — |
| `countdown.start` | Запущен отсчёт | — |
| `background.play` | Фоновая музыка начала трек или продолжила после паузы | `title` (имя файла без расширения, никогда не путь), `resumed` |
| `background.pause` | Фоновая музыка на паузе | `title` |

У `row.stop`, `row.finished` и `row.end` в `row` — строка, которая играла. У
событий без строки — `data.row: null`.

**Изменения состояния** (живут 10 мин):

| `type` | Когда | Доп. поля в `data` |
| --- | --- | --- |
| `row.updated` | **Сырая правка:** оператор закончил править заметку (или текст отсчёта). Ровно одно событие на завершённую правку, при коммите редактора; если значение не изменилось, ничего не шлётся. | `previous`: `{"notes": "старое значение"}` (или `name`) |
| `row.skip` | **Факт:** строка стала пропущенной (появилось слово пропуска) | — |
| `row.unskip` | **Факт:** строка перестала быть пропущенной (слово убрали) | — |
| `row.move` | **Факт:** FestEngine создал или обновил строку-дубль по `>NNN` | `after_num`, `dup_grid_num` |
| `row.unmove` | **Факт:** оператор удалил строку-дубль | `after_num`, `dup_grid_num` отменённого переноса |
| `row.removed` | Оператор удалил строку отсчёта | — (строка как была до удаления) |

Правила для фактов:

- **Порядок:** сначала `row.updated`, потом вызванный им факт — за один проход
  `on_grid_cell_changed`.
- **Пропуск только при смене состояния.** Правка заметки у уже пропущенной
  строки без удаления слова шлёт только `row.updated`.
- **`after_num`** — № строки, после которой **реально** встал дубль:
  `get_num()` ближайшей строки выше, не отсчёта, у дубля — номер исходной
  строки.
  - Это не обязательно цифра из заметки. Если номера 200 нет, будет ближайший
    меньший.
  - Если после 200 уже стоит другой дубль, будет номер исходной строки этого
    дубля.
- **`row.move` — только если дубль реально создан или обновлён.** `>5` (меньше
  трёх цифр) — не перенос, события нет.
- **Удаление дубля** шлёт только `row.unmove`. Форк чистит заметку исходной
  строки программно (`SetCellValue`), а на это wx событие правки не генерирует,
  поэтому `row.updated` не будет.

**Служебное:** `hook.test` (`data: {}`) по кнопке **Send test event**.

### Заголовки

```http
POST <URL>
Content-Type: application/json
User-Agent: FestEngine
webhook-id: msg_<uuid4 hex>
webhook-timestamp: <unix-секунды этой попытки>
webhook-signature: v1,<base64>        ← только если задан секрет
<свои заголовки>                      ← только если заданы
```

- `webhook-id` и `webhook-timestamp` шлются **всегда**.
- `webhook-id` создаётся один раз на событие и тот же при всех повторах.
- `webhook-timestamp` — время попытки, поэтому каждая попытка подписывается
  заново.
- Подпись — HMAC-SHA256 от `"{id}.{attempt_ts}." + body`. Ключ — base64-декод
  части секрета после `whsec_`.

```python
def sign(secret, msg_id, attempt_ts, body):
    encoded = secret[len("whsec_"):] if secret.startswith("whsec_") else secret
    key = base64.b64decode(encoded)
    to_sign = ("%s.%d." % (msg_id, attempt_ts)).encode("utf-8") + body
    digest = hmac.new(key, to_sign, hashlib.sha256).digest()
    return "v1," + base64.b64encode(digest).decode("ascii")
```

Проверено на `Webhook.verify()` из Python-библиотеки `standardwebhooks`.

### Доставка

- **Порядок:** одна FIFO-очередь и один рабочий поток. События приходят в том
  порядке, в каком случились. Следующее не уходит, пока не закончено текущее.
- **Таймаут:** 10 с на попытку.
- **Редиректы** не выполняются. 3xx — это ошибка.

| Ответ | Действие |
| --- | --- |
| 2xx | Доставлено. Тело ответа не читается. |
| 410 | Получатель отписался. Выключить **Send Webhooks**, очистить очередь, показать `410 — disabled`. |
| 429, 5xx, таймаут, нет связи | Повторить то же событие. Пауза 1, 2, 4, 8, 16, 30, 30… с, ±20 % случайного разброса. Если `Retry-After` больше, ждать его. |
| Прочие 3xx/4xx | Отбросить. В лог — код и первые 200 символов тела. |

- **Срок жизни:** сценические команды отбрасываются через 120 с после
  `timestamp`, изменения состояния — через 10 мин. Это осознанное отличие от
  многодневных повторов в Standard Webhooks: события описывают живое шоу.
- **Лимит очереди:** 200 событий. Когда очередь полна, выбрасывается самое
  старое с записью в лог.
- **Галочка:** выключение очищает очередь, включение начинает с пустой.
- **При выходе:** недоставленные события отбрасываются с записью в лог. Рабочий
  поток — daemon.

## A4. Изменения в коде (поверх форка из #177)

### Оставить из форка

- `API Post URL` / `API Post Enabled` и режим `debug`.
- Места отправки `row.show` (обработчик F1) и `row.play` (запуск/F5).
- Пропуски через заметки и логику удаления дубля.

### Поправить в форке

1. **`int(...)` от ячейки №** в `on_grid_cell_changed`.
   - Падает на строках отсчёта (`brk`) и номерах с буквой (`183a`).
   - Исключение вылетает **после** `self.grid.Unbind(EVT_GRID_CELL_CHANGED)` и
     до повторного `Bind`, поэтому обработчик остаётся отвязанным до
     перезапуска, и переносы через `>` перестают работать.
   - Как поправить: строковый `get_num()`, а логику хуков обернуть в
     `try/finally` вокруг `Bind`.
3. **Целые слова** вместо подстроки (`'skip' in note`), список слов из A1.
4. **Конверт** `{type, timestamp, data:{row, …}}` вместо `{num, action}`;
   `new_pos_num` → `after_num` в смысле из A2, плюс `dup_grid_num`.
5. **Доставка:** вместо «поток на запрос без повторов» — отправитель из A2
   (очередь, порядок, повторы, подпись).

### Новый модуль `src/webhook_sender.py` (без импорта wx)

```python
class WebhookSender:
    def __init__(self, on_status, on_log, on_gone): ...  # колбэки из рабочего потока
    def configure(self, url, secret, headers): ...
    def send(self, event_type, data): ...                # не блокирует, ставит в очередь
    def send_now(self, event_type, data): ...            # синхронно, для «Send test event»
    def clear(self): ...
```

- **Из чего собран:** `urllib.request`, `hmac`, `hashlib`, `base64`, `json`,
  `uuid`, `threading`, `queue`, `random`, `datetime`.
- **Редиректы:** `urllib` по умолчанию их выполняет, поэтому нужен свой opener,
  который от них отказывается.
- **Политика повторов и устаревание** — чистые функции, их можно покрыть
  юнит-тестами.

### `src/main.pyw`

- **`send_api_request` → `emit(event_type, data)`.**
  - Сразу выходит, если вебхуки выключены.
  - Учитывает `debug`.
  - Иначе вызывает `self.webhook.send`.
- **`row_payload(row)`** собирает `data.row` в UI-потоке. **Рабочий поток
  таблицу не трогает.**
- **Одно событие на действие:**
  - Shift+F2 → `row.stop`, Esc → `row.end`, Shift+Esc →
    `system.emergency_stop`. `stop_async` у них общий, поэтому сам ничего не
    шлёт.
  - `projector.clear` шлётся только из привязок Shift+F1/Alt+F1.
  - Нет `row.finished` после ручной остановки: `stop_async` красит строку в
    `ROW_SKIPPED` до остановки. Этот порядок сохранить.
- **Фоновая музыка играет в рабочих потоках,** поэтому её события идут через
  `wx.CallAfter`.
- **`on_grid_cell_changed`:**
  1. `row.updated` (если `e.GetString()` отличается от нового значения);
  2. `row.skip` / `row.unskip` (при смене состояния);
  3. `row.move` (если дубль создан или обновлён).
- **`del_row`:** дубль → `row.unmove` (данные собрать **до** `DeleteRows`);
  строка отсчёта → `row.removed`.
- **Строка состояния:** `CreateStatusBar(4)` → `CreateStatusBar(5)`.

## A5. Тесты (`test/test_webhook_sender.py`, `unittest`, без wx)

- **Подпись:** фиксированные секрет, id, время и тело дают ожидаемый `v1,…`.
- **Проверка заголовков:** служебные имена, CR/LF, `Имя: значение: с двоеточием`.
- **Повторы:** паузы и их потолок, `Retry-After`, разброс.
- **Устаревание:** команды через 120 с, изменения состояния через 10 мин.
- **Распознавание пропуска:** целые слова, любой регистр; `skipping intro` не
  считается.
- **Сквозные тесты** против локального `http.server`:
  - 200; 503 → 200 с повтором под **тем же** `webhook-id`;
  - 404 отбрасывается; 410 вызывает `on_gone`; 302 не выполняется;
  - порядок событий сохраняется;
  - свои заголовки на месте, служебные не перезаписываются;
  - без секрета нет `webhook-signature`.
- **Совместимость с библиотекой:** если установлен `standardwebhooks`, его
  `verify()` принимает подпись; иначе тест пропускается.

Для ручной проверки без настоящего получателя — тестовый приёмник
`webhook_receiver.py` (только stdlib: печатает события, проверяет подпись,
отвечает заданной последовательностью кодов).
